# 挑战档 · LLM 自主编排设计

现阶段把人工编排拆成两部分。每题变化的是「原题有哪些独立需求、每个需求怎么写成查询」。共同部分已经固化为 RSI Flow 模板，包括整题检索、两到三个需求检索节点、候选合并和评测。下一阶段优先用 LLM 生成每题的分支配置，由程序根据分支数实例化已有模板并执行。

## 给模型什么，模型输出什么

- **输入**包括题号、原题、当前 RSI 节点及其输入输出说明、分支数量限制、检索参数和两三个已经审过的示例。原题作为待分析文本。官方标注和 A/B 评测结果由评测程序持有。
- **输出**沿用现有配置结构。每个分支需要唯一的 `id`、供画布展示的 `label` 和用于检索的 `query`。分支覆盖原题中可以单独查找能力的交付物，保留必要的技术和约束。分支顺序会影响去重与追加，应按原题明确的依赖或优先级排列。同级需求可沿用原题顺序。
- **固定部分**包括原题检索、已有节点类型、索引及分片、RRF 权重、合并配额和 Top 10。程序根据分支配置映射到固定节点，将各节点候选统一送到合并评测。模型的输出权限限于分支配置。

以复试题 `q-03910` 的现有人工配置为例。以下展示模型将来需要产出的格式，字段和内容取自本次已实测的配置。

```json
{
  "id": "q-03910",
  "title": "提交前密钥扫描插件与提示文案",
  "branches": [
    {
      "id": "plugin",
      "label": "组织插件与扫描入口",
      "query": "Package a Claude Code plugin for staged-file secret scanning with a pre-commit hook, a manually invoked directory scan command, a plugin.json manifest, and a versioned marketplace catalog entry."
    },
    {
      "id": "messages",
      "label": "设计可访问的 CLI 提示",
      "query": "Write concise and accessible command-line copy for a pre-commit secret scanner: detection warning, proceed confirmation, clean scan success, tool failure with next steps, and help on scan patterns. Keep messages in copy/strings.json and explain each wording choice."
    }
  ]
}
```

程序可自动检查题号是否匹配、字段类型、分支数量、分支 ID 唯一性、查询是否为空，并验证模板实例化后的节点连线是否覆盖每个配置分支。通过后以同一原题跑 A/B，留存配置、各节点候选、最终排名和五项指标。运行结束后由评分器单独加载标注。示例题的人工作法已把 `ux-writing` 从 A 的未进前十补到 B 的第 7，最终从 1/2 命中变为 2/2。

## 人工要负责哪些环节

| 环节 | 人工职责与原因 |
| --- | --- |
| 定验收口径 | 固定完全修复标准、保留排名质量指标和复试样本。否则模型或程序可以通过改变比较口径制造表面提升。 |
| 审核含糊需求 | 当原题边界含糊、存在互斥解释或模型报告不能确定时，确认哪些交付物必须覆盖、哪些约束必须保留。结构检查只能验证配置是否可执行。 |
| 审核退化与改变规则 | 逐题区分节点未召回、候选被合并配额挡掉和原有命中被挤后。如 `q-00095` 召回持平但 NDCG 下降，由人工判断是否接受，以及是否批准另起实验调整合并策略。 |
| 处理标注争议 | 如果候选看起来等价，由人工另记语义判断和依据，官方分数仍按官方标注计算。 |

下一阶段可在一批事先锁定的新题上同时跑 A 整题、B 人工分支、C 模型分支，三组共享评测和冻结的检索配置。先记录 C 的格式通过率、可运行率和人工抽查的需求覆盖率，再比较完整修复率、五项检索指标以及逐题退化。将模型的收益和失败同人工操作量一起记录。本交付给出设计和人工运行证据，C 组属于下一阶段的验证。
