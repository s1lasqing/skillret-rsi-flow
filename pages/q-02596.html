整题融合检索

Our React + Node.js app "FieldNote" is being developed by three squads in parallel — Squad A owns the dashboard module, Squad B owns the reporting module, and Squad C owns the settings module — and we keep getting merge nightmares because all three squads are touching shared translation files (`en.json`, `ar.json`, `fr.json`, `ja.json`). We use i18next with react-i18next on the frontend and i18next-http-middleware on the backend, ICU message format for plurals and gender, and we need full RTL support for Arabic. Can you redesign our i18n file structure and namespace strategy so that each squad can add/modify translations independently without conflicting with each other, set up a CI check that detects and blocks translation key collisions before merge, integrate a workflow for pulling approved strings from our Lokalise TMS into the correct namespace, and make sure the build still produces a single optimized bundle per locale at deploy time? Ideally show me the folder layout, the namespace loading config, the CI script, and the Lokalise pull/sync script.
